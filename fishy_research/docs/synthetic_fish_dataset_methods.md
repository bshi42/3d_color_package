# Synthetic fish dataset generation: design, mathematics, and methodology

This document describes the synthetic fish texture datasets generated by
[`color_fishy.py`](../../color_fishy.py) and
[`color_fishy_tps.py`](../../color_fishy_tps.py). It is written as a methods note that can be
adapted for an academic manuscript. The primary validation dataset is the 250-specimen
shared-mesh "fishy" dataset generated by `color_fishy.py`; the later cichlid generator
in `color_fishy_tps.py` extends the same color model to multiple real fish meshes by
using landmark-based canonicalization and thin-plate-spline (TPS) warping.

Code citations are included inline as Markdown links to the implementation line ranges
that define the described behavior.

## Manuscript-ready summary

We constructed a synthetic, fully parameterized fish coloration dataset to evaluate
whether color-based 3D morphospace methods recover known population structure. Each
synthetic specimen used a common UV-unwrapped fish mesh and a procedurally generated
2048 x 2048 RGB texture. Coloration was defined by a small number of anatomically
interpretable volumetric brushes: a yellow body color, blue ventral belly patch, green
tail patch, black transverse stripes, and optional red cheek patches. Continuous nuisance
variation was introduced by Gaussian perturbations of hue, saturation, brightness, patch
position, patch strength, stripe spacing, stripe width, and stripe offset. Four factors
were deliberately planted as known ground-truth structure: two belly-hue clusters, two
tail-hue clusters, a four-stripe versus five-stripe count with probabilities 0.8 and
0.2, and a rare rosy-cheek phenotype with probability 0.05. For each specimen, sampled
generating parameters were stored in `samples.csv`, and the corresponding brush field
was evaluated at all mesh vertices. Vertex colors were written to a Blender corner-domain
color attribute and baked with an emission material to a UV texture, avoiding effects of
lighting or view geometry. Downstream validation used only the generated textures and
mesh geometry; the stored parameters were reserved for ground-truth labels.

## Purpose and design criteria

The dataset was designed as a controlled validation benchmark for 3D color-analysis
workflows. Real biological datasets may contain meaningful color and pattern variation,
but the true generative factors are usually unknown. The synthetic design therefore
separates two roles:

- The rendered textures mimic a biological 3D color-analysis input: textured fish meshes
  with spatially localized color patterns.
- The stored parameter table provides an oracle: each specimen has known latent factors
  against which PCA, ICA, UMAP, clustering, segmentation, and pattern descriptors can be
  scored.

The generator intentionally includes both easy and difficult signals. Belly and tail
hue are strong color-composition signals. Stripe count is a geometric pattern signal
with jittered spacing and offset, so it is not fully described by color composition
alone. Rosy cheeks are a deliberately rare, small-area class, testing whether the
analysis can detect low-prevalence localized variants.

## Primary shared-mesh dataset

The primary dataset contains `N = 250` specimens generated with `SEED = 49`
([code: constants](../../color_fishy.py#L49-L60)). Each
specimen is a 2048 x 2048 PNG texture named `fishy_000000.png`, ..., `fishy_000249.png`.
All textures are baked onto the same UV-unwrapped fish mesh, `fishy1.obj`; therefore,
surface correspondence is exact across specimens and no atlas registration is required
for the synthetic benchmark. The generator also writes one row per specimen to

In the research harness, the corresponding data locations are:

- Shared mesh: `/mnt/data/ml_data/fishy_all/fishy1.obj`

## Color parameter model

All colors are sampled in HSV space and then converted to RGB before painting. Let
`wrap(x) = x mod 1` denote circular hue wrapping, and let `clip(x)` denote clipping to
the interval `[0, 1]`. The fixed palette anchors are defined in the generator
([code: palette constants](../../color_fishy.py#L62-L67)):

| Feature | RGB anchor | HSV anchor symbol |
|---|---:|---|
| Belly blue | `(39, 70, 144) / 255` | `BLUE` |
| Body yellow | `(242, 255, 73) / 255` | `YELLOW` |
| Tail green | `(21, 127, 31) / 255` | `GREEN` |
| Stripe black | `(0, 0, 0)` | `BLACK` |
| Cheek red | `(255, 102, 99) / 255` | `RED` |

For specimen `i`, the parameter vector `theta_i` is sampled as follows.

### Whole-body base color

The body color is a yellow HSV color with independent continuous nuisance variation:

```text
base_hue_i = wrap(YELLOW_h + Normal(0, 0.015^2))
base_sat_i = clip(YELLOW_s + Normal(0, 0.05^2))
base_val_i = clip(YELLOW_v + Normal(0, 0.05^2))
```

This distribution is implemented in `sample_space`
([code: base sampling](../../color_fishy.py#L69-L71),
[code: sampled values](../../color_fishy.py#L105-L109)).

### Stripe parameters

The stripe count is a planted categorical factor:

```text
stripe_count_i ~ Categorical({4: 0.8, 5: 0.2})
```

Stripe geometry also contains Gaussian nuisance variation:

```text
stripe_spacing_i             ~ Normal(0.08, 0.01^2)
stripe_width_i               ~ Normal(0.03, 0.005^2)
stripe_longitudinal_offset_i ~ Normal(0.00, 0.01^2)
```

For the shared-mesh `fishy` generator, the first stripe segment starts at
`a0 = (0.1, -0.25, 0.07)` and ends at `b0 = (0.0, -0.24, 0.17)`. For stripe index
`k = 0, ..., stripe_count_i - 1`, the stripe endpoints are translated by
`k * stripe_spacing_i + stripe_longitudinal_offset_i` along the mesh `y` coordinate:

```text
a_k = (a0_x, a0_y + k * spacing_i + offset_i, a0_z)
b_k = (b0_x, b0_y + k * spacing_i + offset_i, b0_z)
```

Each stripe is mirrored across the fish midline by negating the `x` coordinate of both
endpoints, yielding bilateral stripe pairs.

Each stripe is a capsule brush with **no solid core** (`solid_radius = 0`) and fixed
`strength = 1.0`; the sampled `stripe_width_i` is used directly as the capsule Gaussian
falloff scale `sigma`. Stripes are therefore soft-edged Gaussian tubes rather than
hard-radius bands, and because they are composited last with full strength they overwrite
the underlying body, belly, and tail colors at their cores.
The stripe probabilities, nuisance parameters, and bilateral capsule generation are
implemented in the shared-mesh generator
([code: stripe constants](../../color_fishy.py#L73-L85),
[code: stripe sampling](../../color_fishy.py#L110-L113),
[code: stripe brushes](../../color_fishy.py#L148-L171)).

### Belly color

Belly hue is a planted two-component one-dimensional Gaussian mixture generated with
`sklearn.datasets.make_blobs`. In code, two cluster centers are selected inside
`[-0.1, 0.1]` and samples are drawn with within-cluster standard deviation `0.015`:

```text
belly_shift_i ~ two_component_blob(center_box=[-0.1, 0.1], cluster_std=0.015)
belly_hue_i   = wrap(BLUE_h + belly_shift_i)
```

The saturation and value are fixed at the blue palette values. Belly expression strength
and position are nuisance variables:

```text
belly_strength_i    = clip(Normal(0.95, 0.05^2))
belly_translation_i ~ Normal(0, 0.05^2)
```

In the generator the strength mean is not an independent constant but is defined as
`1.0 - strength_std`; with `strength_std = 0.05` this yields the mean `0.95` above. The
same coupling applies to the tail and cheek strengths, so changing a strength standard
deviation also shifts its mean. The belly mixture and patch brush are implemented in
[`sample_space`](../../color_fishy.py#L114-L117) and
[`generate_belly`](../../color_fishy.py#L179-L183).

### Tail color

Tail hue follows the same planted two-component construction, centered around the green
palette hue:

```text
tail_shift_i ~ two_component_blob(center_box=[-0.1, 0.1], cluster_std=0.015)
tail_hue_i   = wrap(GREEN_h + tail_shift_i)
tail_strength_i = clip(Normal(0.95, 0.05^2))
```

The belly and tail mixtures are sampled independently in the current generator.
The tail mixture and patch brush are implemented in
[`sample_space`](../../color_fishy.py#L118-L120) and
[`generate_tail`](../../color_fishy.py#L185-L189).

### Rosy-cheek minority phenotype

Cheek presence is a planted rare binary factor:

```text
cheek_present_i ~ Bernoulli(0.05)
```

Cheek hue, strength, and position variables are sampled for every row, but they affect
the rendered texture only when `cheek_present_i = 1`:

```text
cheek_hue_i   = wrap(RED_h + Normal(0, 0.015^2))
cheek_strength_i = clip(Normal(0.95, 0.05^2))
cheek_translation_y_i ~ Normal(0, 0.05^2)
cheek_translation_z_i ~ Normal(0, 0.05^2)
```

The cheek Bernoulli variable, nuisance variables, and bilateral cheek brush are implemented
in the generator
([code: cheek constants](../../color_fishy.py#L99-L103),
[code: cheek sampling](../../color_fishy.py#L121-L125),
[code: cheek brushes](../../color_fishy.py#L191-L198)).

## Volumetric brush model

Each color feature is represented as one or more volumetric brushes in mesh world
coordinates. The generator uses two brush types:

- Spherical brushes, parameterized by a center `c`, solid radius `r`, Gaussian falloff
  scale `sigma`, RGB color `q`, and strength `s`.
- Capsule brushes, parameterized by a line segment with endpoints `a` and `b`, solid
  radius `r` (zero unless specified), falloff scale `sigma`, color `q`, and strength `s`.

For a vertex position `p`, the distance to a spherical brush is:

```text
d_sphere(p) = ||p - c||_2
```

The distance to a capsule brush is the distance to the closest point on segment `ab`:

```text
t(p) = clip(((p - a) dot (b - a)) / ||b - a||_2^2, 0, 1)
d_capsule(p) = ||p - (a + t(p)(b - a))||_2
```

Given either distance `d(p)`, the opacity before strength scaling is a hard core with
a Gaussian tail:

```text
alpha0(p) = 1                                      if d(p) <= r
alpha0(p) = exp(-0.5 * ((d(p) - r) / sigma)^2)     otherwise
```

The final opacity is:

```text
alpha(p) = clip(s * alpha0(p), 0, 1)
```

Brushes are composited sequentially over the current RGB value `C(p)`:

```text
C_new(p) = (1 - alpha(p)) C_old(p) + alpha(p) q
```

The brush order in the primary generator is: base body color, belly patch, tail patch,
optional cheek patches, and finally black stripes. Placing stripes last allows them to
visibly overwrite the underlying body, belly, or tail colors.
The distance, falloff, opacity, and compositing operations are implemented in
`apply_brushes` ([code: brush compositing](../../color_fishy.py#L274-L349)); the ordering
is defined in `generate_fishy_coloration`
([code: brush order](../../color_fishy.py#L200-L225)).

## Anatomical brush definitions on the shared fish mesh

For the primary `fishy` dataset, brushes are placed in the coordinate system of the
single fish mesh ([code: brush definitions](../../color_fishy.py#L148-L198)):

| Feature | Brush type and placement |
|---|---|
| Base body | Sphere at `(0.0, 0.0, 0.0)`, solid radius `2.0`, `sigma = 1.0`, sampled yellow color |
| Belly | Sphere at `(0.0, -0.1 + belly_translation, -0.55)`, solid radius `0.5`, `sigma = 0.05`, sampled blue hue |
| Tail | Sphere at `(0.0, 0.5, 0.0)`, solid radius `0.05`, `sigma = 0.2`, sampled green hue |
| Cheeks | If present, bilateral spheres at `(0.07, -0.37 + cheek_translation_y, -0.03 + cheek_translation_z)` and `(-0.07, -0.37 + cheek_translation_y, -0.03 + cheek_translation_z)`, solid radius `0.02`, `sigma = 0.01`, sampled red hue |
| Stripes | Bilateral capsule brushes from `a0 = (0.1, -0.25, 0.07)` to `b0 = (0.0, -0.24, 0.17)`, translated per stripe by the count, spacing, and offset parameters; solid radius `0` (no hard core), `sigma = stripe_width`, `strength = 1.0`, black |

## Procedural texture noise

The generator optionally initializes vertex colors with a deterministic, spatially
smooth grayscale noise field before brush compositing. For a vertex `p = (x, y, z)`,
the scalar field is:

```text
g_raw(p) = [sin(3.1 * scale * x)
          + sin(2.3 * scale * y + 1.7)
          + sin(4.0 * scale * z + 3.4)] / 3
```

The values are linearly normalized over all vertices to `[0, 1]`, replicated into RGB,
and blended with the current color by:

```text
C(p) = (1 - eta) C(p) + eta (g(p), g(p), g(p))
```

The current settings are `eta = 0.10` and `scale = 8.0`. Because the base body brush is
opaque over most or all of the shared fish mesh, this pre-brush noise is most influential
where subsequent brush opacities are less than one or where the base brush does not fully
cover the surface. It is nevertheless part of the deterministic rendering procedure.
The noise constants and sinusoidal field are implemented in the primary generator
([code: noise constants](../../color_fishy.py#L58-L60),
[code: noise field](../../color_fishy.py#L294-L300)).

## Baking procedure

The generator evaluates the final brush-composited RGB value at every mesh vertex. It
then writes these colors to a Blender color attribute named `SynColor` on the corner
domain, assigning each mesh loop the color of its associated vertex. The object receives
an emission material whose color input reads the `SynColor` attribute. A target image
node named `SynTex` is created at 2048 x 2048 pixels, and Blender Cycles bakes an `EMIT`
pass to that image with bake margin 16. Because the material is emissive and the baked
pass is `EMIT`, the saved texture encodes the procedural color field directly, without
illumination, shadows, or camera effects. The texture is saved as PNG.
The implementation is split across vertex-color writing, emission-material setup, and
Cycles baking
([code: vertex colors](../../color_fishy.py#L351-L369),
[code: bake material](../../color_fishy.py#L371-L396),
[code: bake call](../../color_fishy.py#L398-L415)).

The primary generator writes:

```text
samples.csv
fishy_000000.png
fishy_000001.png
...
fishy_000249.png
```

## Ground-truth labels for validation

The generator stores continuous parameters rather than only class labels. The research
harness derives labels as follows:

- `belly`: two classes recovered by one-dimensional k-means on `belly_hue`, with cluster
  IDs ordered by increasing hue.
- `tail`: two classes recovered by one-dimensional k-means on `tail_hue`, with cluster
  IDs ordered by increasing hue.
- `stripe`: binary label `0` for four stripes and `1` for five stripes.
- `cheeks`: binary label equal to `rosy_cheeks_present`.

The labels are used only for validation and reporting. The unsupervised analysis methods
consume the rendered textures, mesh, and derived per-face colors, not the labels.
Label derivation is implemented in `fishpipe.data`
([code: k-means hue labels](../src/fishpipe/data.py#L88-L95),
[code: ground-truth labels](../src/fishpipe/data.py#L98-L113)).

## Texture-to-surface sampling for downstream analysis

For experiments that compare the generated textures to morphospace or clustering
outputs, textures are converted to per-face RGB values using the same operation as the
3D Slicer analysis module. For each triangular mesh face, the texture is sampled at the
three UV corner coordinates using nearest-neighbor pixel lookup with the V coordinate
flipped, and the three sampled RGB values are averaged:

```text
RGB_face(f) = [RGB(u_1, v_1) + RGB(u_2, v_2) + RGB(u_3, v_3)] / 3
```

The harness also computes each triangle area:

```text
area(f) = 0.5 * ||(p_2 - p_1) x (p_3 - p_1)||_2
```

and centroid:

```text
centroid(f) = (p_1 + p_2 + p_3) / 3
```

These quantities support area-weighted color histograms, spatially flattened color
vectors, side-view renderings, and structural pattern descriptors.
The OBJ loader, face geometry, UV sampling, and cached per-face tensor are implemented in
the research harness
([code: mesh representation](../src/fishpipe/mesh.py#L23-L49),
[code: OBJ loader](../src/fishpipe/mesh.py#L52-L87),
[code: texture sampling](../src/fishpipe/mesh.py#L90-L104),
[code: cache builder](../src/fishpipe/data.py#L41-L75)).

## Cross-specimen cichlid extension

The `color_fishy_tps.py` generator extends the same brush-based color model to real
cichlid meshes with different shapes. This extension is useful for testing the full
atlas-transfer pipeline, where coloration must be placed in homologous anatomical
locations across specimens rather than on a single fixed mesh. The current script uses
seven source cichlid meshes and their 3D Slicer landmark JSON files, chooses specimen 0
as the reference, and generates `N = 25` samples with `SEED = 49`. In that variant,
`ROSY_CHEEKS_PROB = 0.5`, making the cheek phenotype common enough to inspect in a small
pilot dataset.
These cichlid inputs and pilot-dataset constants are specified in the TPS generator
([code: cichlid paths](../../color_fishy_tps.py#L42-L61),
[code: TPS constants](../../color_fishy_tps.py#L63-L117)).

### Landmark canonicalization

For each specimen, the generator reads defined 3D Slicer fiducial landmarks and partitions
selected labels into semantic groups: front, back, top, and bottom. It computes a semantic
pivot `c0` from front/back and top/bottom centroids when available. A proper rotation is
then estimated by a Wahba/Kabsch-style SVD solution that aligns landmark displacement
vectors to canonical anatomical axes.

Let `G` be the set of constrained landmark groups, let `a_g` be the target unit axis for
group `g`, let `w_g` be its weight, and let `p_l` be a landmark position. The script builds:

```text
M = sum_g sum_{l in G_g} w_g a_g (p_l - c0)^T
```

If `M = U S V^T`, the rotation is:

```text
R = U D V^T
D = diag(1, 1, sign(det(U V^T)))
```

After rotation, the fish is scaled so the distance between the rotated front and back
centroids is one. It is then translated so the back centroid is at the canonical origin.
For any world coordinate `p`, the canonical coordinate is:

```text
p_can = scale * (p - c0) R^T + translation
```

The inverse transform used to return canonical points to a specimen's world coordinates is:

```text
p_world = ((p_can - translation) / scale) R + c0
```

Landmark loading, semantic grouping, canonical rotation/scale/translation, and inverse
coordinate transforms are implemented in
[`load_slicer_markups_json`](../../color_fishy_tps.py#L130-L158),
[`spring_pull_rotation`](../../color_fishy_tps.py#L186-L242),
[`compute_canonical_transform`](../../color_fishy_tps.py#L254-L294), and the transform
helpers ([code: transform helpers](../../color_fishy_tps.py#L301-L312)).

### Thin-plate-spline anatomical warp

Let `X = {x_j}` be the reference specimen landmarks in reference canonical space, and let
`Y = {y_j}` be the matching landmarks for specimen `i` in specimen canonical space. A
regularized 3D TPS warp `f_i` is fit from `X` to `Y`. The implemented radial basis kernel is:

```text
U(r) = r^2 log(r + epsilon)
```

with `epsilon = 1e-12`. The fitted map has the form:

```text
f_i(p) = sum_j U(||p - x_j||_2) W_j + [1, p_x, p_y, p_z] A
```

where `W` contains non-affine radial weights and `A` contains the affine component. The
linear system can be written as `L Z = B`, where:

```text
L = [[K + lambda I, P],
     [P^T,          0]]

Z = [W; A]
B = [Y; 0]
```

where `K_jk = U(||x_j - x_k||_2)`, `P_j = [1, x_j[0], x_j[1], x_j[2]]`, and
`lambda = 1e-6`. At least four shared, non-coplanar landmarks are required. The script
records the number of shared landmarks and the landmark-fit RMSE for each specimen.
The regularized TPS fit, evaluation, and specimen preprocessing are implemented in
`TPS3D` and `preprocess_specimens`
([code: TPS class](../../color_fishy_tps.py#L319-L412),
[code: specimen preprocessing](../../color_fishy_tps.py#L419-L495)).

### Warping brush geometry

Brushes are first generated in the reference canonical coordinate system. For a spherical
brush, the center is mapped by:

```text
c_spec_can = f_i(c_ref_can)
c_world    = canonical_to_world_i(c_spec_can)
```

For a capsule brush, both endpoints are mapped in the same way. Brush radii and Gaussian
falloff scales are multiplied by an estimated local scale factor of the reference-canonical
to specimen-world transformation. The TPS local scale is estimated by finite differences:

```text
scale_TPS(p) = (1/3) sum_{axis=1}^3
               ||f_i(p + eps e_axis) - f_i(p - eps e_axis)||_2 / (2 eps)
```

with `eps = 1e-5`. The final scale factor is:

```text
scale_total(p) = scale_TPS(p) * (1 / specimen_scale)
```

For capsules, the endpoint scales are averaged. After this transformation, the same
volumetric brush equations are evaluated on the selected specimen's world-space mesh
vertices, then baked to texture.
Brush warping and local scale propagation are implemented in
[`warp_brushes`](../../color_fishy_tps.py#L715-L767); the TPS generator reuses the same
brush compositing, vertex-color, material, and bake logic
([code: TPS brush compositing](../../color_fishy_tps.py#L634-L708),
[code: TPS bake helpers](../../color_fishy_tps.py#L815-L875)).

### Cichlid extension outputs

The TPS generator writes one image, copied mesh, copied landmark file, and metadata row

## Reproducibility notes

- The primary dataset is deterministic given the Python, NumPy, scikit-learn, and Blender
  execution environment, the selected fish mesh, and `SEED = 49`.
- The `make_blobs` calls use scikit-learn's active random state when `random_state` is not
  explicitly passed, after NumPy has been seeded. Reproducing exact hue clusters therefore
  requires a compatible scikit-learn/NumPy environment.
- The rendered PNGs are baked by Blender Cycles. Small pixel-level differences may occur
  across Blender versions or GPU/CPU bake backends, but the sampled parameter table and
  intended brush geometry define the dataset mathematically.
- The ground-truth table should be archived with any generated texture release. The
  texture files alone are sufficient for unsupervised analysis, but the table is required
  for quantitative validation.

## Limitations and intended use

This dataset is not intended to be a photorealistic ecological simulator. It is a
controlled algorithmic benchmark whose visual features are deliberately simple,
interpretable, and parameterized. Its value is that the analyst knows which factors
should be recoverable and which factors are intentionally challenging. Results on this
dataset should therefore be reported as validation of sensitivity to known color and
pattern structure, not as evidence that the synthetic images span the full complexity of
natural fish coloration.
