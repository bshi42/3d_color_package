# Tagging Morphospace — static build

A **fully client-side** version of the multi-label tagging demo: no Python server, no backend. The expert
creates tags, clicks a tag to make it the active class, then clicks specimens to toggle it (multi-label), and
after every batch a per-tag classifier retrains
and a 2-D *latent morphospace* + clustering tree update live — all computed in the browser.

It mirrors the served demo one level up (`../`, i.e. `fishy_research/expert-tagging-demo/`) feature-for-feature;
only the compute moved to JS.

> This directory is **gitignored** except the hand-authored source (`engine.js`, `index.html`, `lib/`, this
> README). `app.js`/`style.css` are generated by `../build_static_frontend.py`; `bundle_*.json` + `thumb*/` are
> baked by `../export_tagging_static.py`. After a fresh checkout, run both (see *Re-baking* below) to populate them.

## Run

```bash
python3 -m http.server 8771 -d .      # from this dir; any static file server works
# open http://127.0.0.1:8771
```

## What runs where

| Piece | Served demo (Python) | Static build (browser) |
|---|---|---|
| descriptor → PCA-24 coords (`Z`) | computed live | **baked** into `bundle_<ds>.json` |
| cold-start novelty score | computed live | **baked** into the bundle |
| thumbnails | rendered on demand | **baked** PNGs in `thumb/`, `thumb_hi/` |
| per-tag classifier | sklearn `LogisticRegression(C=0.5, class_weight='balanced')` | `engine.js` IRLS port (matches sklearn, decision-score err < 1e-2) |
| latent → 2-D | warm-started UMAP (python) | warm-started **umap-js** (`lib/umap-js.min.js`) |
| active learning / novelty roll | engine | `engine.js` |
| Ward latent tree | scipy | `engine.js` (Lance-Williams) |

## Files

- `index.html` / `style.css` — UI (identical layout to the served demo).
- `app.js` — same UI logic as the served demo; its `api()` now dispatches the old server routes into a
  client-side `TagEngine` instead of `fetch`-ing a backend.
- `engine.js` — the pure port (`TagEngine`): logistic + umap-js projection + novelty/uncertainty rolls +
  Ward tree. Runs in the browser and in node (so it can be unit-tested headless).
- `bundle_<ds>.json` — `{names, Z (N×24), novelty, leaf_aspect}` per dataset.
- `lib/umap-js.min.js` — vendored [umap-js](https://github.com/PAIR-code/umap-js) (UMD, `window.UMAP.UMAP`).

## Re-baking the build

From the served demo dir one level up (`fishy_research/expert-tagging-demo/`), with the fishy_research venv:

```bash
cd ..
../.venv/bin/python export_tagging_static.py     # bundles + thumbnails -> static_demo/
python3 build_static_frontend.py                 # app.js + style.css   -> static_demo/
```

## Limitations vs the served demo

- The classifier latent is projected with **umap-js**, not Python UMAP. Warm-starting keeps the map stable
  as tags accumulate (≈33 % less inter-batch motion than a fresh fit, and converging), but the exact layout
  differs from the Python build — the *structure* is equivalent, the pixels are not.
- Datasets are fixed to what was baked (`mussel`, `fishy`). Adding one means re-running the export.
